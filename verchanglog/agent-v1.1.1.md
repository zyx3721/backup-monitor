## 📋 版本概述

本版本修正 `agent-v1.1.0` 状态文件判定的移植偏差，恢复原版 Agent 1.2.32 的进程探测口径。

`agent-v1.1.0` 引入了「状态文件缺少 `end` 时给 15 分钟窗口」的逻辑，但把「没有配置 `proc` 关键字」误当成「进程探测不可用」，同时丢失了原版的关键字回退。结果是没有 `proc` 标签的长任务（例如耗时数小时的 rsync）在状态文件只有 `start`、进程仍在运行时，会在第 15 分钟被误判为「执行中断」。

本版本恢复原版行为：

- 进程关键字依次取任务 `proc` 标签、脚本名、任务名；
- `proc.Running` 同时返回「是否命中」与「进程列表是否可用」；
- 探测可用但未命中时立即判为执行中断；
- 只有进程探测本身不可用时，才使用 15 分钟兜底窗口。

---

## ✨ 新增特性

本版本未新增采集来源、协议字段或配置项。

判定行为调整如下：

- 状态文件只有 `start`、没有 `end` 时，进程关键字按以下顺序回退：
  1. 任务标签 `proc` / `process`；
  2. 任务配置 `script` 的文件名；
  3. 任务名。
- 命中进程：判为运行中，消息为「执行中」。
- 进程探测可用但未命中：立即判为失败，消息为「执行中断（缺少结束时间）（状态文件路径）」。
- 进程探测不可用：15 分钟内判为运行中，消息为「执行中（进程探测不可用，按时间窗口判定）」；超过 15 分钟仍无 `end` 判为失败。

## 🐛 Bug 修复

- 修复没有 `proc` 标签、但备份进程仍在运行的长任务在第 15 分钟被误判失败的问题
- 修复把「未配置进程关键字」误当成「进程探测不可用」的问题
- 修复 `proc.Running` 只返回是否命中、无法区分「未命中」与「探测不可用」的问题

## 🔧 重构优化

- `proc.Keyword` 改为可变参数，按顺序返回首个非空候选
- `proc.Running` 改为返回 `(found, available)`，缓存同时保存进程列表可用性
- Linux / Windows 进程列表实现统一返回可用性标记
- `collect` 新增 `taskKeyword` 与 `scriptName`，进程探测、状态文件判定和 `proc` 执行消息复用同一关键字
- 补充多候选关键字、探测可用性与状态文件缺少 `end` 的单元测试
- 同步 `agent/README.md` 与 `agent/README.en.md` 的进程关键字与状态文件判定说明

## 🔄 升级说明

**建议升级**，尤其是存在以下情况的主机：

- 备份任务没有配置 `proc` 标签；
- 状态文件只写 `start`，`end` 在备份结束后才写入；
- 单次备份耗时超过 15 分钟。

本版本只修改 Agent 采集判定，不涉及上报协议字段，兼容现有服务端；服务端无需同步升级。

升级方式：

1. **管理端推送**：在「Agent 管理 → Agent 更新」上传对应平台二进制，选择匹配槽位后推送；Agent 会校验 SHA-256 并重启自身
2. **手工覆盖**：停止 Agent 服务，用新二进制覆盖原文件后重新启动；不要移动或改名二进制文件
3. **Windows 7 / Server 2008 R2**：使用 `*_windows_amd64_legacy.zip`，只能停服务后手工覆盖，不要上传管理端

升级后，仍在运行的备份任务会在下一次采集时以相同 `sessionId` 重新上报为运行中，服务端会更新原记录；任务结束后再上报成功或失败。已经结束但被误判为失败的历史记录不会自动改写，如需修正可删除该条执行记录后重新采集。
