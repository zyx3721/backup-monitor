## 📋 版本概述

自托管备份监控平台的第一个正式版本。它解决的是备份运维最常见的一个盲区：备份脚本、计划任务与 Veeam 作业**跑没跑、跑没跑成、没人知道**——通常要等到恢复演练或数据丢失时才发现漏备。

本版本的思路是用一个轻量 Agent 贴着被监控主机做无侵入采集，把「计划」与「实际执行」一起上报，由 Go 服务端统一比对判定，异常进入告警中心并按渠道分发。Agent 不修改任何既有备份脚本，只读取 crontab、Windows 计划任务、Veeam 配置与产物元数据。

首版覆盖完整闭环：Agent 采集 → 服务端判定 → 告警通知 → 管理端处置 → 审计留痕。

## ✨ 新增特性

### 备份监控核心

- **主机管理**：主机名、节点 ID、IP、操作系统、角色、Agent 版本、在线状态与任务数；支持搜索、状态与平台筛选、级联删除
- **任务发现**：Linux `crontab`、Windows 计划任务（优先 PowerShell，`schtasks` / COM 回退）、Veeam Job 与手工登记任务四类来源，支持按标签与关键字过滤
- **执行记录**：会话 ID、执行状态、触发方式、开始与结束时间、备份体积、产物路径、退出码与错误信息
- **状态判定**：正常 / 运行中 / 失败 / 未执行 / 无数据五种状态；统计连续失败次数与成功率
- **告警中心**：覆盖备份失败、未按时执行、主机异常三类事件；支持去重、自动恢复、按状态/类型/级别筛选与导出
- **通知分发**：邮件、WebHook、企业微信、钉钉、飞书五种渠道；按事件类型与级别订阅，保留发送记录。企业微信/钉钉支持 Markdown，飞书支持富文本与卡片；飞书 `receive_id` 可填多个接收人，卡片标题栏按测试/恢复（绿）与告警（红）着色

默认判定阈值（可在「系统配置 → 基础配置」调整）：

- 主机上报超时 **3 分钟**判异常、**6 分钟**判离线
- 计划时刻后 **30 分钟**仍无执行记录判「未执行」
- 计划匹配窗口 **60 分钟**，巡检间隔 **30 秒**
- 执行记录、发送记录、审计日志默认保留 **90 天**

### Agent（独立二进制）

- **无侵入采集**：只读 crontab、计划任务与 Veeam 配置/状态，不注入、不改写既有备份脚本
- **服务化运行**：Linux 通过 `-install` 注册 systemd 单元，Windows 注册系统服务；均支持 `-once` 前台试跑
- **长连接与指令下发**：WebSocket 通道承载配置变更、在线改 cron、Agent 自更新，Agent 回执后管理端展示结果
- **自更新**：服务端托管各平台二进制，按版本比对后推送升级；升级前校验 SHA-256
- **二进制分发**：管理端按「平台 + 架构 + 通道」托管 5 个槽位（linux/amd64、linux/arm64、windows/amd64、windows/arm64 为标准包，windows/amd64 另有 legacy），支持公开下载链接供首次部署使用；通过扫描二进制内置版本标记识别版本
- **Windows 兼容包**：legacy 包使用 Go 1.20 构建，覆盖 Windows 7 SP1 / Server 2008 R2 SP1；主机上报 `arch` 与 `osBuild` 后，推送与自动更新按架构和构建号选包
- **本地状态与日志**：状态文件记录上次执行与采集结果，日志按大小与份数轮转

### 管理端

九个页面：概览、备份主机、备份任务、执行记录、告警中心、通知管理、Agent 管理、系统配置、审计日志。

- **概览**：主机/任务/今日执行/成功率/异常任务/未处理告警六项指标，14 天趋势、状态分布、异常任务与最近告警
- **备份任务**：按主机/方式/状态筛选，查看执行历史与采集配置，在线修改 cron 并等待 Agent 回执
- **Agent 管理**：采集配置、Agent 令牌、Linux/Windows 二进制分发与自更新推送
- **系统配置**：基础配置（品牌标识、安全时效、判定与保留、Agent 通道、安全与告警）、用户配置、认证配置、找密配置

### 认证与权限

- **三种登录方式**：本地密码、AD/LDAP、企业微信扫码（直连模式与统一认证中心 SSO 模式）
- **找回密码**：图形验证码 + 邮件链接，带发送冷却与一次性令牌校验
- **登录失败锁定**：连续失败达到阈值后按分钟级窗口锁定，内置 `admin` 不受限
- **权限体系**：23 个权限项，按九个侧边栏分类组织；`manage` 通过隐含关系自动包含 `read`
- **页面级拦截**：缺少集合 `read` 时不渲染页面并给出提示，缺少概览权限时自动跳首个可访问集合；顶部告警铃与全局搜索同样按权限裁剪
- **审计留痕**：登录、配置变更、任务与告警操作全程记录，记录来源 IP 与操作结果

### 部署与交付

- **Docker**：`linux/amd64` + `linux/arm64` 双架构镜像，同步推送阿里云镜像仓库与 Docker Hub
- **Release 二进制**：后端覆盖 linux/darwin/windows × amd64/arm64 六平台，附前端 SSR 产物包与 `SHA256SUMS`
- **Nginx + systemd**：手册提供服务端、控制台与 HTTPS 的完整反代示例
- **两条发布流水线**：应用（`v*`）与 Agent（`agent-v*`）分开发布，互不触发

### 技术架构

| 层 | 技术 |
| --- | --- |
| 后端 | Go 1.25、chi v5、modernc.org/sqlite（WAL）、JWT、gorilla/websocket |
| 前端 | React 19、TanStack Start / Router / Query、Tailwind CSS 4、Radix UI |
| Agent | 独立 Go module（go 1.22），15 个内部包，按 `_linux.go` / `_windows.go` 隔离平台差异 |

代码规模：后端与 Agent 共 180 个 Go 文件约 3.3 万行，前端 119 个 TS/TSX 文件约 2.0 万行。

## 🐛 Bug 修复

首个版本，无对外历史缺陷修复项。开发过程中一并处理的边界问题列示如下，便于后续维护时定位：

- 企业微信统一认证中心模式的回跳路径改为 `/login`，与直连模式的 `/wecom-qr-callback` 区分，避免认证中心侧填错路径导致扫码后无法回跳
- Agent 版本号统一从源码读取，`-version` 输出与管理端识别的版本保持一致，避免出现「客户端显示新版、服务端识别旧版」
- 判定任务「未执行」时跳过已停用任务与超出匹配窗口的计划，减少误报

## 🚀 性能优化

- SQLite 连接池固定 `MaxOpenConns(1)` 配合 WAL，把并发写入交给单连接串行化，规避 `database is locked`
- 判定巡检按 30 秒间隔批量处理，执行记录按 `(task_id, session_id)` 幂等写入，重复上报不产生重复记录
- 前端列表与看板使用 TanStack Query 缓存与失效策略，切换页面不重复拉取全量数据

## 🔧 重构优化

- 后端按「路由层 / 服务层 / 仓储层 / 领域模型」四层拆分，路由按 `common`、`auth`、`settings`、`system`、`backup` 分域
- `agent/` 独立为 Go module，禁止反向依赖 `backend/`，平台差异通过构建标签隔离
- 前端按「路由页面 / 复用组件 / 业务域组件 / 工具库」分层，业务域组件集中在 `features/`

## 📊 数据库变更

首个版本建库，共 **25 张表**：16 张平台表 + 9 张备份监控表。

- 平台表：`users`、`roles`、`user_roles`、`user_groups`、`user_group_members`、`user_group_roles`、`sessions`、`system_secrets`、`basic_config`、`auth_config`、`pwd_recover_config`、`reset_captchas`、`reset_requests`、`reset_send_log`、`login_failure_log`、`audit_logs`
- 备份监控表：`hosts`、`tasks`、`executions`、`alerts`、`agent_profiles`、`agent_tokens`、`agent_binaries`、`notify_channels`、`notifications`

建库入口为 `backend/router/system/db.go`（bootstrap 表）与 `backend/router/system/schema.go` 的 `EnsureRuntimeSchema`；备份监控表由 `backend/internal/repository/backup_schema.go` 的 `EnsureBackupSchema` 幂等创建。启动时按顺序执行，只保留初始化建表与种子数据，不做独立增量迁移。

## 🔄 升级说明

**全新安装，无历史版本需要迁移。**

1. 首次启动会自动建库并写入种子数据，默认账号 `admin / admin123`，**登录后请立即修改密码**
2. 生产环境必须设置 `JWT_SECRET`；未设置时服务端会生成并存于 `system_secrets` 表
3. Agent 需单独部署到被监控主机，在管理端「Agent 管理」创建令牌后按 `docs/agent-protocol.md` 配置 `serverUrl` 与 `token`
4. Docker 部署只挂载 `backend/data/` 即可保留数据库；二进制部署注意 `.env` 与工作目录
5. 反向代理需设置 `X-Forwarded-For`，否则审计与登录日志记录的都是代理地址
