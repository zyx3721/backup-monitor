## 📋 版本概述

v1.1.3 修复两个与「执行失败」相关的问题：

1. **Agent 状态文件缺少结束时间时长期显示运行中**：备份进程中断、状态文件只有 `start` 没有 `end` 时，Agent 会一直上报运行中，记录只能等下一次计划执行才被服务端关闭。本版本恢复原版判定口径，进程已退出或超过时间窗口时上报「执行中断（缺少结束时间）」。该修复已单独随 **agent-v1.1.0** 发布，线上 Agent 需要单独升级。
2. **执行详情弹窗不展示失败原因**：执行记录接口一直返回 `message`，但前端详情弹窗没有渲染。本版本在失败记录上方补充红色「执行失败」横幅，显示具体错误信息。

---

## ✨ 新增特性

- **执行详情失败横幅**：`state === 'failed'` 时，在详情表格上方显示红色提示，标题「执行失败」，内容为「错误信息：<message>」；成功与运行中状态不显示
- **明暗主题适配**：横幅复用现有 `bm-event-tone-danger` 语义色，浅色主题使用深红文字、浅红背景，深色主题使用浅红文字、低透明度红背景
- **Agent 状态文件判定补充**：只有 `start`、没有 `end` 时，按「进程命中 / 配置了 proc 但进程退出 / 未配置 proc 的 15 分钟窗口」三条路径判定

---

## 🐛 Bug 修复

- **状态文件缺少结束时间长期运行中**：修复 Agent 对 `HasStart && !HasEnd` 无条件上报 `running` 的问题；备份进程中断后会在下一轮采集上报失败，不再等待下一次计划执行
- **中断记录 endTime 误显示开始时间**：执行中断记录不再回填 `endTime`，与服务端原版口径一致
- **Windows 状态文件来源同样受影响**：Linux 与 Windows 共用采集逻辑，`veeam-status` 等状态文件来源一并修复
- **执行详情不显示失败原因**：补充失败横幅，打开历史失败记录即可看到已存储的 `message`

## 🔄 升级说明

1. **应用升级**：替换后端二进制（或更新 Docker 镜像）并重启；前端需重新构建部署，失败横幅包含在新前端产物中
2. **Agent 升级**：状态文件判定修复已随 `agent-v1.1.0` 发布，需要在「Agent 管理 → Agent 更新」推送新二进制，或停服务后手工覆盖
3. **历史记录收敛**：Agent 升级后，下一轮采集会以相同 `sessionId` 重新上报历史中断记录为失败，服务端直接更新原记录并把任务状态改为失败，无需手工改库
4. **兼容性**：Agent 协议未变化，服务端无需同步升级；未升级的 Agent 仍可正常上报，但缺少结束时间的记录仍会停留在运行中
5. **告警**：历史记录转为失败后会按现有规则产生「备份失败」告警；如需清理由告警中心处理
