## 📋 版本概述

本版本修复状态文件采集的一个关键判定缺陷：状态文件只有 `start`、没有 `end` 时，Agent 会无条件上报「运行中」，备份进程中断后记录会一直停留在运行中，直到下一次计划执行才被服务端关闭。修复后恢复原版 Agent 的判定口径，进程已退出或超过时间窗口时上报「执行中断（缺少结束时间）」。

Linux 与 Windows 共用同一套采集逻辑，两个平台同时生效。

---

## ✨ 新增特性

本版本未新增采集来源、协议字段或配置项。

判定行为补充如下：

- 状态文件只有 `start`、没有 `end` 时，按以下顺序判定：
  - 命中 `proc` 进程关键字：判为运行中，消息为「执行中」
  - 配置了 `proc` 但进程已退出：立即判为失败，消息为「执行中断（缺少结束时间）（状态文件路径）」
  - 未配置 `proc`：先给 15 分钟窗口，窗口内判为运行中，消息为「执行中（进程探测不可用，按时间窗口判定）」
  - 未配置 `proc` 且超过 15 分钟仍无 `end`：判为失败，消息为「执行中断（缺少结束时间）（状态文件路径）」
- 执行中断记录不再回填 `endTime`，与服务端原版口径一致，避免把开始时间误显示为结束时间

## 🐛 Bug 修复

- 修复状态文件缺少结束时间时执行记录长期显示「运行中」的问题
- 修复备份进程中断后不会产生失败告警、也不会触发通知的问题
- 修复 Windows 上 `veeam-status` 等状态文件来源同样可能长期停留在运行中的问题

## 🔧 重构优化

- 将状态文件的「运行中」判定从单一分支拆为「进程命中 / 进程探测可用 / 15 分钟窗口」三条路径，判定条件集中在一个函数内，便于后续扩展
- 补充 5 组单元测试，覆盖进程命中、进程退出、窗口内、窗口外与 `status=running` 但已过期等场景
- `agent/README.md` 状态文件章节补充缺少 `end` 时的判定口径

## 🔄 升级说明

**建议升级。** 本版本只修改 Agent 采集判定，不涉及上报协议字段，兼容现有服务端；服务端无需同步升级。

升级方式：

1. **管理端推送**：在「Agent 管理 → Agent 更新」上传对应平台二进制，选择匹配槽位后推送；Agent 会校验 SHA-256 并重启自身
2. **手工覆盖**：停止 Agent 服务，用新二进制覆盖原文件后重新启动；不要移动或改名二进制文件
3. **Windows 7 / Server 2008 R2**：使用 `*_windows_amd64_legacy.zip`，只能停服务后手工覆盖，不要上传管理端

升级后，主机下一次采集会以相同 `sessionId` 重新上报历史中断记录为失败，服务端会直接更新原记录并把任务状态改为失败，无需手工改库。若线上存在长期「运行中」的历史记录，升级后会自动收敛。
