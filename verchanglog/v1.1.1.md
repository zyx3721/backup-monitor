## 📋 版本概述

v1.1.1 修复 v1.1.0 遗留的判定误报：计划匹配由「取最近一条非手动执行记录」改为「查询计划窗口内是否存在记录」，并把窗口上界收敛到当前时刻。

修复后，Agent 或 Veeam 主机时钟略快导致的「下一周期记录提前入库」不再污染上一周期判定；窗口内已有的成功记录也不会被之后产生的补跑、重试记录顶掉。迟到语义保持不变，真正的迟到仍判为未按时执行。

## 🐛 Bug 修复

- **计划匹配改为窗口内存在性判断**：在 `[计划时刻 − 窗口, min(计划时刻 + 窗口, 当前时刻)]` 区间内查找非手动执行记录，命中即采用该记录状态，不再用「全局最近一条记录」反推本次计划
- **排除未来记录**：窗口上界收敛到当前时刻，晚于服务器时间入库的记录不参与判定，消除「计划时刻前几十秒误报上一周期未按时执行」的现象
- **更晚记录不再顶掉窗口内成功记录**：窗口内已有成功执行时，即便之后存在窗口外的补跑、重试记录，仍判定为正常
- **迟到语义保留**：窗口内确实没有记录、且窗口结束后另有记录时，仍判「未按时执行」，告警文案保留「执行记录晚于匹配窗口」的区分

## 🔧 重构优化

- 仓储层以 `ScheduledExecutionWithin`（窗口内最近一条）与 `ScheduledExecutionAfter`（窗口之后最近一条）替代 `LatestScheduledExecution`，计划匹配只查询所需区间
- 移除 `EvaluateTask` 中不再使用的 `statusFromScheduled` 辅助闭包
- 新增 3 条回归用例：下一周期记录提前入库、窗口内成功记录与窗口外记录并存、仅存在迟到记录

## 🔄 升级说明

1. 直接替换后端二进制（或更新 Docker 镜像）并重启服务，判定逻辑即时生效
2. **升级前产生的未执行告警不会自动恢复**：其所属计划周期已无法再匹配到窗口内记录，建议在告警中心人工恢复或清空
3. Agent 无需升级，上报协议与字段均未变化
4. 本次修复只避免误判，不修改写入的时间戳；若执行记录时间明显超前于服务端时间，建议核对 Agent 与 Veeam 服务器的 NTP 时钟同步
